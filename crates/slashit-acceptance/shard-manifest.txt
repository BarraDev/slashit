# Desktop acceptance product-journey shard manifest.
#
# Every test name printed by:
#   cargo test -p slashit-acceptance --features run-acceptance --test product_acceptance -- --list
# must appear here exactly once, in exactly one shard. scripts/check-acceptance-shards.sh
# enforces that in CI (the "Lint, test and build" job): a new journey with no entry here, a
# stale entry for a renamed or removed journey, or a journey listed under more than one shard
# all fail that check. scripts/run-desktop-acceptance.sh --shard <N> reads this file to pick
# which journeys a shard runs, both in CI and locally.
#
# The harness suite (tests/acceptance.rs) is not sharded; it always runs whole, in its own CI
# job ("Desktop acceptance / harness"), and does not belong in this file.
#
# Shards are balanced by measured hosted-CI duration, not by test count, using the
# `--test-threads=1` per-test timings from CI run 36669879622 (commit b1313670, the run this
# manifest was built against): shard totals are 163.8s / 165.6s / 165.3s out of 494.7s. The two
# ~78s cleanup-refusal journeys (NO_RETRY_WINDOW) are deliberately split across different
# shards. Rebalance by editing this file; the coverage check does not care about balance, only
# about complete, non-overlapping assignment.
